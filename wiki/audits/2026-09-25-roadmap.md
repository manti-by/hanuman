# Roadmap & Architecture for Electrical Regulatory RAG (Belarus)

This document maps out the document structuring, metadata schema, and chunking strategy required to build a specialized Retrieval-Augmented Generation (RAG) system for the Belarusian electrical engineering domain based on the [hanuman repository](https://github.com/manti-by/hanuman/).

---

## 🛠 Repository Integration & Configuration Adaptations

The current `hanuman` codebase defines a general-purpose text chunking flow using environment variables:
*   `CHUNK_SIZE`: 1000 tokens/characters
*   `CHUNK_OVERLAP`: 200 tokens/characters

For a highly precise regulatory RAG covering **Engineering (Case 1)** and **Procedural/Legal (Case 3)** domains, relying solely on a generic `RecursiveCharacterTextSplitter` with arbitrary character sizes will cause broken tables, lose nested multi-tier cross-references, and hallucinate structural norms. 

The configuration needs to transition towards **Hierarchical / Markdown Splitting with Target Metadata Filtering**.

---

## 📂 Domain 1: Engineering, Design & Installation (Case 1)
Focuses on technical rules, design requirements, and safe installation.

### Key Documents & Target Sections
1.  **ТКП 339-2022 (with Izmenenie No. 1, 2025)** — *Core Base Blueprint*
    *   **Section 4 (Protective Measures):** Earthing (заземление), protective bonding, RCDs (УЗО), TN/TT/IT systems.
    *   **Section 5 (Switchgear & Substations):** Clearances, equipment ratings, electrical safety layouts.
    *   **Section 7 (Wiring & Metering):** Cable sizing, types of insulation, metering placement, and conduit layouts.
2.  **СН 4.04.01-2019 (Residential & Public Buildings)** — *Internal Infrastructure*
    *   **Text & Tables:** Load profiles, demand coefficients, emergency/escape lighting, socket circuits, and main distribution boards (ВРУ).
3.  **СН 4.04.05-2025 / СП 4.04.07-2025 (External Networks)** — *Outside Plant*
    *   **Text & Geometry:** Trench depths, clearances between electrical lines and parallel utilities (gas, water, communications), overhead line (ВЛ) buffers, and structural safety zones.
4.  **Soviet ПУЭ-6 (Remaining chapters)** — *Legacy Fallback*
    *   **Chapter 1.2:** Reliability Categories (1st, 2nd, 3rd categories of electrical receivers).
    *   **Section 3:** Relay protection and automation frameworks.

### Extraction & Chunking Strategy
*   **Table Pre-processing:** Electrical standards rely heavily on multi-variable matrices (e.g., cross-sectional area vs. maximum continuous current). Raw text conversion splits these into contextless rows. You must parse PDF tables using tools like `LlamaParse` or native PyPDF table extractors, rendering them into clean **Markdown tables** or standalone **JSON blocks** wrapped in conversational wrappers before ingestion.
*   **Hierarchical Structural Markers:** Instead of dividing by 1000 characters, use a `MarkdownHeaderTextSplitter` split along document headers (`#`, `##`, `###`, down to clause integers like `4.2.1.1`).

## ⚖️ Domain 3: Procedural & Administrative Grid Connection (Case 3)
Focuses on connection logistics, bureaucratic compliance, and regulatory interfaces.

### Key Documents & Target Sections
1.  **Rules of Electricity Supply (Правила электроснабжения Республики Беларусь — Resolution of the Council of Ministers No. 1394)**
    *   **Sections on Grid Connection:** Procedural path for obtaining technical specifications (Технические условия - ТУ), signing electrical supply agreements, and defining legal borders for asset ownership and operational liabilities (Границы балансовой принадлежности и эксплуатационной ответственности).
2.  **Presidential Decree No. 200 (Administrative Procedures for Individuals)**
    *   **One-Window Protocol Extracts:** Legally binding processing timelines, document checklists, and application terms for physical citizens connecting properties or upgrading power limits (e.g., 15 kW distribution setups for residential space heating).

### Extraction & Chunking Strategy
*   **Temporal Version Control:** Unlike engineering constants, legal decrees change rapidly via amendments. Maintain an absolute timestamp metadata field (`updated_at`) for every clause block to prevent the LLM from surfacing obsolete administrative timelines or expired sub-rules.
*   **Parent-Child Context Binding:** Legal clauses are often written as an administrative checklist branching off a single root sentence. Keep parent context linked directly into small sub-clauses so the text embedding retains the legal subject matter.

## 🏷 Metadata & Filtering Architecture

To enable targeted query pre-filtering in `hanuman`'s `pgvector` store and mitigate cross-domain hallucinations, extend your chunk document schema with the following structured metadata attributes:

| Field Key | Type | Description / Allowed Values | Usage Example |
| :--- | :--- | :--- | :--- |
| `doc_id` | String | Reference identifier for the parent code. | `"TKP-339-2022"` / `"SN-4.04.01-2019"` |
| `domain` | String | Separation of target system audiences. | `"engineering"` (Case 1) / `"procedural"` (Case 3) |
| `voltage_class` | String | Scope of electrical pressure limits. | `"up_to_1000v"` / `"above_1000v"` / `"any"` |
| `facility_type` | String | Concrete real estate / engineering context. | `"residential"`, `"industrial"`, `"external_grid"` |
| `structural_ref` | String | Precise document breadcrumb tracking. | `"Chapter 7, Clause 7.1.2.3"` |
| `last_verified` | String | ISO Date for tracking regulatory validity. | `"2025-08-01"` |

## 🚀 Recommended Immediate Next Steps for the Hanuman Repository

1.  **Add Domain Filtering Flags to the CLI:**
    Modify `hanuman/main.py search` to accept structural argument overlays. This forces the vector query to constrain its search boundaries rather than pulling irrelevant industrial rules for residential citizen questions.
    ```bash
    python main.py search "Какие документы нужны для ТУ на 15 кВт?" --meta "domain:procedural"
    ```
2.  **Upgrade the Ingestion Engine (`hanuman/main.py index`):**
    Replace standard text loaders with markdown/document structure chunkers. Ensure that tables are explicitly captured without breaking their visual or text coordinates.
